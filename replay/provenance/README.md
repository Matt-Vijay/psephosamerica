# Inert accepted-source provenance

The `.py.txt` files are exact, content-addressed historical source evidence, not runnable modules. Never import, execute, or resolve file paths found inside them. The New Jersey source includes historical machine-path strings in report metadata; those inert labels remain verbatim solely to preserve its accepted hash. Maintained replay entrypoints use project-relative inputs and separate reviewed parsers.

`../catalog.json` selects only the 45 published batches named by the accepted summary. It distinguishes acceptance-attested code from three currently observed, originally unsealed helper files. Identical source bytes share one snapshot, with original project-relative aliases retained. Ten already tracked code blobs, including the six historical core modules, are referenced by full Git revision and path rather than duplicated.

The archive excludes raw legal payloads, worker stores, logs, test/self-check/finalization scripts and unrelated discovery code. Maryland probe.py contains an imported runtime budget class; Utah discover.py contains its CLI acquisition class and is preserved for that role. Kansas runtime.py is likewise a CLI acquisition dependency. Shared sources.py contains dormant baseline dispatch imports; those unrelated adapters are outside this archive and never invoked by replay.

Historical source alone is not a replay guarantee. The catalog records external sidecars, unsealed dependencies, finalized metadata and historical representation gaps. Only Florida, New Jersey and Mississippi are marked supported_offline; that support comes from the maintained replay modules, not from these inert files. All other batches remain provenance_only, with maintained core source families separately identified.

No acquisition, source-store or canonical-store writes are authorized by this archive. `/text-2` accepted identity and projections must not be confused with current `/text-3` output.
